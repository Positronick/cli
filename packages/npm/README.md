# npm packages (wired up, publish gated on one-time bootstrap)

npm distribution for the Positronick CLI, using the esbuild/biome
optionalDependencies pattern:

```
packages/npm/
└── positronick/            # the package users install: `npm i -g positronick`
    ├── package.json        # bin: positronick + pck; optionalDependencies on the
    │                       # four platform packages below
    └── bin/
        ├── positronick     # Node shim: resolves the platform package's binary
        │                   # and spawns it (with a curl|sh fallback hint)
        └── pck             # alias — requires the same shim
```

## How it works

The `positronick` package contains no binary. It declares
`optionalDependencies` on four platform packages —
`@positronick/cli-{linux,darwin}-{amd64,arm64}` — each of which sets
`os`/`cpu` in its package.json so the package manager installs exactly one of
them. The `bin/positronick` shim resolves
`@positronick/cli-<os>-<arch>/bin/positronick` at runtime and spawns it,
forwarding argv, stdio and the exit code. If the platform package is missing
(unsupported platform, or optional deps disabled) the shim fails loudly and
points at `curl -fsSL https://positronick.com/install.sh | sh`.

## Publish flow (CI, at release time)

On each `v*` tag, the `npm` job in `.github/workflows/release.yml`:

1. downloads the released `positronick_<os>_<arch>.tar.gz` archives from the
   GitHub release and verifies them against `checksums.txt`;
2. runs `scripts/build-npm-packages.sh`, which generates the four
   `@positronick/cli-<os>-<arch>` platform packages from the archives and
   copies this meta-package with every `0.0.0-placeholder` version (and the
   optionalDependencies pins) rewritten to the released version
   (`scripts/test-build-npm-packages.sh` covers it, runs in CI and
   `make check`);
3. `npm publish`es the platform packages first, then the `positronick`
   meta-package, via npm Trusted Publishing (OIDC, with provenance — no token
   secret).

The platform packages are generated by CI from the release archives; only the
meta-package is committed here.

## One-time bootstrap (manual, before the job can run)

The job is gated on the `NPM_PUBLISH` repository variable because Trusted
Publishing can only be configured on packages that already exist:

1. claim the names: `npm publish` the `positronick` meta-package and the four
   `@positronick/cli-*` platform packages once by hand (any placeholder
   version, `--access public` for the scoped ones);
2. on npmjs.com, configure GitHub Actions Trusted Publishing for all five
   packages: repository `Positronick/cli`, workflow `release.yml`;
3. set the `NPM_PUBLISH` repository variable to `true` on `Positronick/cli`.
